Schedule: every member that runs on its own

Every member that runs on its own keeps one card, content/admin/members/<id>/card.json: its objective, when it wakes (London time), the model, the session, the repositories to attach, the steps of each wake, what it reads, writes and never does, and two prompts word for word, the start prompt for a new session on any Claude account and the wake prompt for the scheduled task. A card is proposed until the editor's go creates the task; every wake leaves a run record, so a missing record is a missed wake. The protocol every wake follows is WAKE.md; the brief is schedules, cards and start pages. Nothing here is a secret, and nothing here creates a schedule: the editor does, per card, from the member's page. 8 card(s), 0 active, 16 wake(s) a day, as of 26 Oct 2026.

Setting a member up on any Claude account

  1. Open the member's page and read its card: the repositories, the session name, the start prompt, the cron, the wake prompt.
  2. On the account, start a session with those repositories attached (push access) and name it as the card says.
  3. Paste the start prompt. The session reads the guidance, its page and the board, and replies with its role, what it may and must not do, where it writes, and what waits on it.
  4. With the editor's go, create one scheduled task on that account: the card's name and cron, firing into that session, with the wake prompt word for word. The session then makes the card active in its next release and records the task's id in its status.
  5. A key the role needs is handed sealed to the session's key, never pasted: the handover.
