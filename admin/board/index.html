The board: tasks and requests

Every piece of work on SHarness as one row, numbered so it can be referred to from any page, commit or conversation, and never renumbered. R is a request: it needs the editor (a decision, a key, a setting) and says what it blocks. T is a task: work a member has or anyone can pick up. One file per row under content/admin/board/; the Sherpa keeps the rows honest and scopes them into releases, the conductor builds this page from them, and anyone opens a row by adding a file (how). 10 request(s) wait on the editor and 11 task(s) are open, as of 25 Oct 2026.

T14The row shape in policy.py, so that policy check derives the barrier kind per row. From the PBP on one page §4 and §5: a policy row is subject, resource, operation, predicate (where), held_by and a derived kind. sharness-ai policy check should compute, for every behaviour row, whether its preconditions hold (the capability rows close every other path to the resource; one edge to the keeper) and report the barrier kind: Boundary when they do, Expectation when they do not, never an error. The summary then counts rows held by the kernel, rows held by a keeper and rows unheld, beside hello's probes held. Opened by sharness.pbp, who writes the shape; sharness.build or sharness.dev write the code. The first predicate to carry is append_only, because sharness.fs is its keeper in the design.
