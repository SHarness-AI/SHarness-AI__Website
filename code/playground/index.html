Playground: sharness-ai in Pyodide and in Linux

Two runtimes, one page, nothing installed on your machine. On the left, Pyodide: Python compiled to WebAssembly, where pip install sharness-ai installs the CLI and you can hash, check and translate Process Behaviour Policies. Switch to Linux: Alpine with a Landlock kernel, booted by v86 in this tab, where every sharness-ai run is enforced by a real kernel. On the right, one policy, hashed by three implementations.

What each tab can show. Pyodide has no kernel and no processes, so run and hello refuse there with exit 126: there is no child to confine, and the CLI says so rather than pretend. In Linux every policy is applied by the shell's sharness-ai to its child: a Boundary for the child, a Setting for the shell, which could have skipped it. The kernel is real; the CPU is emulated, so a command takes seconds. The wheel is the CLI's dev branch, versioned +dev.<commit>; PyPI carries only releases. Built and tested as of 26 Oct 2026, with the CLI's new screens (sharness-ai guide --once, policy new, policy show, components; the design): 17 of 17 headless checks held on the files this page serves. The milestone behind it: Linux in a tab.

Things to try

  • Pyodide: pip install sharness-ai, then sharness-ai policy translate policies/p1-agent-session.json --to claude-code: the same policy as Claude Code sandbox settings, followed by what that sandbox cannot enforce. Then sharness-ai hello, and read why it refuses.
  • Linux: sharness-ai hello (six probes under a deny-all policy, 6 of 6 when the kernel holds), then the chips: a write refused under P2, port 80 refused under P1, 200 MiB refused under P0's 64 MiB cap, a wrong --expect-hash that runs nothing.
  • Your own policy: edit the JSON on the right, press Hash it in three places, then Use it, and run something under policies/my-policy.json in Linux. Remove /lib from exec and watch every dynamic binary fail to start: the ELF interpreter needs the execute right too.

The code is one ES module, playground.js, in the CLI repository's experiments/browser/, with a headless test that drives both tabs (test_playground.mjs: Pyodide loads and installs, four commands give the expected output, the guest boots to a shell, hello holds 6 of 6, a write is refused, the three hashes agree). The scripted run of the same guest, without a shell, is the E09 page; what it shows and does not is on Linux in the browser.
