Status: a recommendation, as of 25 Oct 2026, for roadmap decision 11. What each part of SHarness is written in, what it should be written in, and why. The rule behind every row: reuse what Linux and the standard library already have before writing anything, and keep each piece small enough to read in one sitting.

Two rules that follow

  1. Python until a caveat says otherwise. Every component starts in Python because the experiments do and because the design's own figures were measured there. A component moves to Rust only for a stated reason (memory hygiene in the KMS; a static binary for the bash client), recorded on the roadmap.
  2. No runtime dependencies in the CLI beyond cryptography for the components that seal and sign. The experiments stay standard-library only so a Claude session can install and run them anywhere Python is.

Reference implementations in several languages (decided 26 Oct 2026)

Decided by the editor on 26 Oct 2026 (R8): one repository per language, each with the same structure, so that a component or a CLI can ship in that language on its own; the standards and their test vectors on this site (Standards); the first implementation of a component written in the language that suits it, not ported from Python. On the same day the policy v0 standard was written and two implementations passed all of its vectors; the registry says which. Dinis Cruz's brief of 25 Oct 2026 extended decision 11 from "which language for each component" to "reference implementations of each component in several languages, against one standard per component, with test vectors and a reviewed registry". The developer agent's map of that is the article One standard, many languages: what in each component is a specification (the policy's shape and hash, the manifest and the edges, the KMS, net, fs, llm and bash protocols, hello's six expectations) and what is an implementation (reaching the kernel, serving mutual TLS, holding a secret), then a component-by-language matrix.

The rules above still hold: Python until a caveat says otherwise, and no runtime dependencies beyond a stated, pinned exception. What changes is that the exception list grows by one per language (rustls in Rust; nothing in Go or Node), and that each implementation must pass the same test vectors (the seven example policies and their hashes, hello's six expectations) before it enters the registry. The repositories are R21; the registry of implementations is on Standards.

What this does not decide

Whether the platform-provided versions of the components (topology E) share any code with these; the design says only that the protocol is the same. And nothing here is a commitment of sgit's maintainers about sgit's own language, which is Python today.
