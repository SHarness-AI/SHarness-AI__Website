About and naming

By Dinis Cruz. Design session written up with Claude, 24 October 2026.

SHarness is unrelated to Sharness, the shell testing library derived from Git's test suite (felipec/sharness).

The name

SHarness is a secure harness: the layer agents run inside so that they run securely. It takes behaviour policies from text the agent reads to rules the agent runs inside, enforced from outside the agent's environment. Dinis Cruz's memo on the name and the direction is the article A secure harness for agents.

Naming rules

  • The brand is SHarness. Lower-case sharness appears only in code identifiers (sharness.kms, sharness_ai).
  • There is no plain sharness command: on Debian, pkgsrc and OpenBSD that name is the unrelated shell test library's package. The command is sharness-ai.
  • Environment variables use SHARNESS_AI_, not SHARNESS_, which the shell test library uses.
  • One role, one noun: each component is named for its one job.

Where it came from

SHarness grew out of sgit, the encrypted vault CLI, and uses sgit's PKI. The first analysis was A vault key that never lands; the handover it builds on is pki.sgit.ai/handover.md; its policies apply the Agent Behaviour Policy model to processes. sgit is the first app designed to run inside SHarness.

What is real today

The name, this site, and a package with the first experiments. The sharness-ai package on PyPI (v0.1.0, as of 24 Oct 2026) reports its version and prints its help; its dev branch carries experiments E01 to E04 (probe, policy hash, run, hello), unreleased. No SHarness component is built. The status of every claim is on Evidence and What exists today.
