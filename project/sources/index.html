How this pack relates to sgit's

The design began as cli.sgit.ai's sealed vault keys design pack. Compared against the sgit pack's documents 00–04 as Dinis Cruz shared them, as of 24 Oct 2026: 01, 02 and 03 here are identical; 00 here adds documents 05–07 to the reading list and the note on names; 04 here adds §7, the observation of the agent loop. Nothing in the sgit pack's 00–04 is missing from this one. The sgit pack also has a 05, compatibility and rollout (with nothing switched on, sgit behaves exactly as 0.24.0 does; sealed and plain clones side by side; staged rollout), which is sgit-specific and is linked, not republished.

The evolution, on cli.sgit.ai

SHarness began as a fix for sgit, and that history is published where it happened:

  1. A vault key that never lands: the analysis that started it, the morning of 24 October 2026.
  2. Sealed vault keys in sgit: requirements, from an agent that moves vault keys for a living, the same day.
  3. The requirements and the design, side by side: the two read against each other and against the code.
  4. Sealed vault keys for sgit: a design pack: the sgit-specific design, with its compatibility and rollout document.
  5. The SHarness design pack, above: the same design, generalised.

Known issues in the pack

Published as received, so these remain in the raw files:

  • 00-README.md links 05-the-sharness.md; the file is 05-sharness.md.
  • Documents 01–04 use the sgit-specific component names (sgit-cli, sgit-fs, sgit-net, sgit-kms); document 05's diagram uses harness.<role> where the rest of the pack uses sharness.<role>. The site's pages use sharness.<role> throughout.
  • The pack lists the command name as open; it was settled as sharness-ai the same day (see Roadmap).
