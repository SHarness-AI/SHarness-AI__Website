From [the PBP on one page](../../design/pbp/index.md) §6, at the editor's direction of 26 Oct 2026 (databases are the use case that makes the behaviour rows real). A door for one SQLite file, standard library only (`sqlite3`, `http.server`, `ssl`): it receives structured requests (`select`, `insert`, `update`, `delete` with table, columns, a filter, values), never a query string, and answers against the rows of the calling subject's policy: tables and columns allowed, a row filter, value ranges, rows per operation, a total per interval. Its own PBP allows one file under `files.write`; the app's excludes it, so the app reaches rows only through the door (a Boundary for the app, by the rule in §4). Within the component size target. Run under `sharness-ai run` with its policy, and `hello`-style probes: a row outside the filter refused, a value outside the range refused, a second insert over the count refused. Measured means a date and the kernel. Follows T14 (the row shape); read the security register before touching `run.py`.
