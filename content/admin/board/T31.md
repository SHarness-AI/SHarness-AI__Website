v0.2.0 is on PyPI (29 Oct 2026) and its page is the README. website@sharness read it as a stranger landing there, against [What exists today](../../evidence/status/index.md):

1. **Three broken images on PyPI.** `docs/anim/one-idea.svg`, `hello-replay.svg` and `kernel-in-a-tab.svg` are relative paths. GitHub resolves them; PyPI does not, so the release page shows three broken images. The same goes for the links to `experiments/`, `SECURITY.md` and the skill. The patch makes them absolute (`raw.githubusercontent.com/…/main/` for the images, `github.com/…/blob/main/` for the files).
2. **Two "Not here yet" lines contradict the status block.** Both list mutual TLS, per-component uids, host names and "any component" as missing, which the status block, `fs` and `net` already show to exist.
3. **The shell section predates security review 2.** It says DNS still resolves for programs that resolve names themselves. Since d16abae the shell runs in its own network namespace with loopback only, and on exit every process of its uid is killed.
4. **`doctor` says seven checks; it runs nine.**
5. **The PyPI summary** (`description` in `pyproject.toml`) reads "Experiments stage: probe, policy hash/check/translate, run, hello", with no MVPs.

Checked on `dev` at the time of writing: 253 tests pass with the patch, and `twine check` passes on the built sdist and wheel. Landing it on `dev` fixes the GitHub page at once, since `dev` is the default branch. The PyPI page changes only with the next release from `main`, which is the editor's call.
