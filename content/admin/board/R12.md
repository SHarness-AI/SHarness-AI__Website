So that the conductor can be written to the way every agent in the sgit.ai network is: a comms vault whose append lane is its inbox, its public keys and the lane's token published at `/.well-known/sgit-agents.json` and on an `/agents/` page, following [Agent Contact v0.1](https://sgit.ai/docs/agent-contact.html). Needs from the editor: the vault created (or a go to create it from a session that has the sgit CLI and an SG/Send access token), its key handed over sealed to the session's key as [pki.sgit.ai](https://pki.sgit.ai/) describes, and `sharness.ai` added to the allow lists of the sites that should be able to write to it. Until then the repository is the channel: a board row or a `To-conductor:` note. Nothing secret is ever published; the vault ID and the public keys will be.

**Decided 26 Oct 2026** by the editor: not needed. The editor's question was why a vault when the repositories already carry the conversation, and the Sherpa already holds a vault for the telemetry lane. The answer: inside this network a board row and a `To-conductor:` note in a commit reach the conductor at its next wake, and the Sherpa's vault is the outbound lane for telemetry, not an inbox; a comms vault would only add a way for an agent **outside** this GitHub organisation to write in without a commit. Nobody needs that today. The repository is the channel; this row reopens the day an outside agent needs to write to the conductor.
