The security review of 25 Oct 2026 ([Reviews](../../security/reviews/index.md), register row [SR-24](../../security/risks/index.md#the-register)) found `main` and `dev` of both repositories unprotected, one account administering both, and a push to the CLI's `main` publishing to PyPI. Nothing in a repository can change these; [Hardening §3](../../security/hardening/index.md#3-the-repositories-and-the-accounts-settings-only-a-person-can-change) is the checklist, with the weight of each item: two-factor for the organisation; branch rulesets on `main` and `dev` requiring a pull request and the `tests`, `security` and `codeql` checks, blocking force pushes and deletion; a tag ruleset for `v*`; secret scanning with push protection; Dependabot alerts; private vulnerability reporting; the Trusted Publisher on PyPI bound to a `pypi` environment with a required reviewer; Pages deploying only from Actions and only from `dev` and `main`. One decision inside it: the release workflow pushes a version-bump commit to `main`, which a ruleset blocks unless the Actions actor is on its bypass list; the alternative is to derive the version from the tag in the build job and never commit it from CI. The editor sets these and ticks them; the security agent confirms what the API shows afterwards.

**26 Oct 2026, the editor:** confirmed as the editor's to do; no change in the repositories until then.
