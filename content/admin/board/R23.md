The editor's question of 26 Oct 2026, answered in [CI owns the version](../briefs/2026-10-26__brief__ci-owns-the-version/index.md): the send repository's pipeline (the OSBot `git__increment-tag` action, inlined in the CLI's `workflow.yml` since the security review) has CI choose the next number from the tags inside one serialised job, write it to one file, commit, tag and push; the website has the committer guess the number before the push and CI check it, which is what stuck the site twice tonight (T21). To decide: adopt the scheme on the website and extend it to the CLI's `dev` (every push to `dev` tagged); the file at the root of every repository as `/version`, the language repositories included; the words (the editor's *major* and *minor* for the middle and the last number, or the workflow's *minor* and *patch*). After the decision: website@ for the workflow, `ship.py` and the gate with security@'s review; cli@ for the CLI; dev@ for the language repositories and the registry.
