The editor's ask of 26 October 2026. sgit-ai 0.25.0 reached PyPI at 07:38 UTC with the fix for the slowness large vaults had under 0.24.0 ([the release notes](https://cli.sgit.ai/docs/update-to-0-25-0.html): a one-file commit on a 76,000-file vault from 29 minutes to under 5 seconds, `status` from 71 seconds to about 4; the command reference unchanged, 165 commands). Every member whose session touches a vault runs `sgit update` and `sgit version` at its next wake and says so in a `To-conductor:` note (`sgit-ai v0.25.0`). Anything odd afterwards goes in the same note with the command, the vault's size and the timing; a suspicion of data loss (an edit a commit skipped, a pull that overwrote) is said at once. The conductor collects the reports here and carries them to the sgit CLI team. Known from the notes: the first `status` in an existing clone takes once as long as a full hash of the tree (47 seconds on 76,000 files); two new cache files under `.sg_vault/local/` hold file names in clear; a pull that brings another clone's commits and a three-way merge are still the old speed; on Windows the change-time guard does not hold. The conductor's own container is on 0.25.0 (installed 26 October, 08:05 UTC); no SHarness session holds a vault yet (R12), so the first reports will come from the Sherpa's two vaults.
