From [the PBP on one page](../../design/pbp/index.md) §6, at the editor's direction of 26 Oct 2026: a twin is a target with the real thing's signature, named in the invocation layer of the policy, so the same door runs under two hashes, `target: twin` and `target: live`. The test vectors for a target are therefore written once and run first against its twin. The first pair: `sharness.fs.s3` (not yet designed in detail) against [the AWS twin](https://aws.twin.sgit.ai), whose Python twin answers S3's REST-XML and STS with boto3 unchanged; the probes are the door's refusals (a bucket outside the allowlist, a write to a read-only prefix, an object over the size cap, a delete when the policy allows none) and one allowed round trip, each saying which layer refused. Connectedness is a separate measured fact, never implied by a passing suite. For dev@sharness (the standards and their test vectors), with the twins site's owner for the twin's side.
