Seen on 26 Oct 2026 at 02:08 UTC, cutting v0.6.0 on `main` at the editor's request. The push to `main` ran the gate and `tag-release` (v0.6.0 tagged on `27d164a`), then its `deploy` job was refused before any step ran, the shape of an environment protection rule: the `github-pages` environment allows deployments from `dev` only ([R2](index.md#r2) set it that way for the first release). The site still went live at v0.6.0 a minute later, from the `dev` run on the same commit (dev is fast-forwarded to main after a minor, as the README says), so nothing was lost; but a minor release that relies on the next `dev` push to deploy is a red run on `main` every time. In the repository's settings, Environments, `github-pages`, deployment branches: add `main` beside `dev`. One setting; nothing in the repository can change it. After it, the next minor deploys from its own run.
