From R8's decision. The GitHub app this session runs under cannot create a repository in the organisation (`POST /orgs/SHarness-AI/repos` answered 403 on 26 Oct 2026), so the editor creates them: `SHarness-AI__JS`, `SHarness-AI__Go` and `SHarness-AI__Rust`, public, Apache 2.0 like the CLI, **empty** (no README, no licence, no `.gitignore`: the trees carry their own), with `dev` as the default branch once pushed. Suggested descriptions: *SHarness in JavaScript, for Node and the browser: a reference implementation of Process Behaviour Policies against the standard on sharness.ai, checked by its test vectors in CI. Experiments stage*; the same with *Go: ... a static binary* and *Rust: ... the KMS and the bash client are its first targets*. Then dev@sharness pushes each staging branch as that repository's `dev` (`git push <repo> claude/js-reference:dev`), and the Claude GitHub App needs the new repositories in its installation so a session can push to them. Until then the trees are the CLI repository's branches `claude/js-reference`, `claude/go-reference` and `claude/rust-reference`, and [the registry](../../code/standards/index.md#3-the-implementations) says so.

**26 Oct 2026, the editor:** confirmed as the editor's to do; the implementations stay on their staging branches until the repositories exist.
