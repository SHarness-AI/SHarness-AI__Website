Evidence

Every figure on this page was observed as of 24 Oct 2026, in one Claude agent workspace (claude.ai, cloud session). One environment, one day. Re-run the probes before relying on them elsewhere: other platforms, and later versions of this one, may differ.

Three labels are used across the site, and this page is where they are earned:

LabelMeans
measuredprobed or timed in the environment below, with the method stated
designed / proposeda description of how SHarness would work; nothing is built
not yet measurednamed in the design, not tested: seccomp filters, read-only bind mounts, every side door on Enforcing the process tree, and AWS KMS compatibility

Every reported hello run, ours and yours, is on hello on your machine.

6. Transport

Python ssl, TLS 1.3, P-256; the server is a thread in the benchmark process.

Session CA + four role certificates (P-256, 2 h validity): 24 ms.

Edge enforcement with roles in subjectAltName URIs, policy fs←{cli}, net←{cli}, kms←{net} (the probe named the app role cli, as sgit's CLI):

cli → fs   OK        fs  → kms  DENY
cli → net  OK        cli → kms  DENY
net → kms  OK        fs  → net  DENY

Figures are from the final of three runs. Across runs, round trips and bulk varied by up to ~25% (TCP mutual TLS bulk: 250, 275, 318 MB/s; Unix mutual TLS bulk: 349, 378, 418 MB/s); handshake times were stable. Microsecond figures are noisy because the server thread shares Python's interpreter lock with the client: treat them as upper bounds.

The timings are of a single emulated core and are not a measurement of the harness. Dinis Cruz's run of the published page in Chrome on Dinis's own machine, the same day (as of 25 Oct 2026, read off the page's clock in the screenshots; the browser version and machine not recorded): hello exit at 28.5 s, guest done at 32.2 s, every line as above. Write-up and what it does not show: Linux in the browser; the story with the screenshots: Linux in a tab.

The playground, measured 25 Oct 2026 (as of 25 Oct 2026, headless Chromium 153 against code/playground served from this site's tree, test_playground.mjs): Pyodide 314.0.7 loaded in 3.2 s and pip install sharness-ai (the dev wheel, by micropip) finished by 3.8 s; policy hash, translate, probe gave the expected output and hello refused with exit 126; the Linux guest reached its shell in 38.8 s, hello held 6 of 6, P2 refused a write; P0 hashed identically by WebCrypto, Pyodide and Linux; 11 of 11 checks, no page errors.

The example policies P0 to P4, run natively 25 Oct 2026 (as of 25 Oct 2026, uid 0, a stand-in workspace): P0 refused a 200 MiB allocation under its 64 MiB cap (MemoryError); P1 connected to 1.1.1.1:443, was refused on port 80 (EACCES) and wrote the workspace; P2 was refused writes to the workspace and /tmp and the connect; P3 wrote out/ and was refused vault/; P4 ran sgit 0.24.0 --version and pki list, wrote vault/, was refused out/, connected on 443 and read its own hash from SHARNESS_AI_POLICY_HASH. Files and the table: Mockups and experiments.

What this does not show. The policy was applied by the session to its own children. It is a Boundary for them and a Setting for the session (the same root process that could have skipped it). It says nothing about seccomp, uids, cgroups, mutual TLS or the process tree, none of which the experiments touch yet.

Documented, not yet exercised

  • A Claude Code PreToolUse hook can replace a tool's input before it runs (updatedInput, documented 24 Oct 2026), which answers Agents §2 row 3. Not yet exercised on a pinned version.

Not yet measured

  • seccomp filters (available in the kernel; no filter tested)
  • read-only bind mounts (namespaces tested; read-only binds not separately)
  • every side door on Enforcing the process tree: the proof of concept has not been run
  • AWS KMS asymmetric RSA-4096 with OAEP-SHA-256 matching sgit's envelope
  • the experiments E01 to E04 on a laptop (no root; on Ubuntu 24.04 an unprivileged user namespace may be refused, so network: "none" falls back to Landlock's TCP rules, which do not cover UDP)
